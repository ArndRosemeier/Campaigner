# 05 — UI Specification

Tailwind + shadcn/ui, dark mode default (GM-at-the-table friendly), light mode
toggle in the top bar. Routing via react-router.

## Routes

```
/                              → campaign picker
/c/:campaignId                 → three-pane workspace
/c/:campaignId/a/:artifactId   → workspace with artifact open
/c/:campaignId/graph           → link graph
/c/:campaignId/modules         → module list
/c/:campaignId/m/:moduleId     → module reader (the only play view)
/c/:campaignId/m/:moduleId/battle → module's live battle table
/c/:campaignId/deliverables    → deliverable builder
/rules                         → rules library
/settings                      → settings
```

Top bar: app name, campaign switcher, Rules / Settings navigation, New Module
on campaign routes, Ctrl+K quick-find, generation language, help and theme.
Directly below it, the **campaign bar** renders the campaign-level tabs —
Workspace / Modules / Deliverables / Graph — on every route, disabled (with an
"Open a campaign first" hint) while no campaign is open. On nested screens the
bar's right side shows a breadcrumb (Campaigns / Modules / *module title* / Battle
table), so deep screens always state where they are and exit in one click.
The retired `/play` route and `▶ Play` button do not exist.

### Quick-find (Ctrl+K)

The palette follows the workspace scope preference. Artifact hits search
name/tags/summary/aliases; global hits are labeled **Library**. Module/part and rule
hits share the palette. Enter navigates to an artifact or module; rule hits
open an inline preview with **Pin to Assistant**. With an empty query the
palette lists a **Go to** group — the campaign sections (Workspace, Modules,
Deliverables, Graph), Rules and Settings, and **Battle table (this module)**
on a module reader screen — so Ctrl+K doubles as an app map.

## Progress dock

The app-wide dock reports every slow task (batch generation, module parts,
PDF builds). Jobs that live somewhere (a persona run, a module mid-forge)
render their label as an **Open** button that navigates to the job — a run
opens preselected in the workspace persona panel (`?run=`), a module opens in
its reader. A module that is being forged also shows the live step ("Writing
part 2 of 5: …") on its Modules list row.

## Screen: Module reader (`/c/:campaignId/m/:moduleId`) — M6

The module reader is the only play view: table of contents/search on the left,
adventure prose and wiki-link chips in the center, entity panel on the right.
Its shared Library / Campaign / Module scope control defaults to all scopes.
**Battle table** opens the module's live board — offered both in the reader
header (a mode change, visible even with the contents sidebar collapsed) and
in the contents sidebar. Encounter rows offer **Run battle**. Module-owned
rows can be adopted back into the campaign. Recorded
encounter entities can be batch-detailed, and **Generate encounter maps** runs
a one-candidate unattended queue for module encounters still lacking layouts;
failures remain retryable and do not stop later jobs.

## Screen: Battle table (`/c/:campaignId/m/:moduleId/battle`) — M6-E

Full-screen dark board rendered from one module-anchored battle row. Seeding
an encounter replaces that module's prior live board after confirmation;
**Back to module** exits the surface to the module reader (a direct link, not
history-dependent). `data-player-safe="true"` marks Player view.

The DOM carries only board-safe material: map, grid, staging ground, visible
tokens, HP meters, veils/fog, initiative and toolbar—never stat text, notes or
secrets. Veiled mob tokens are removed from the DOM in player view (coverage
hides mobs only — PCs and other tokens are never coverage-hidden and render
above the veil), `visible: false` tokens in both views. Amended 2026-09-06 by
8fa7abd: *veils previously removed any overlapping token in both views at
~100% opacity; veils now tint the map ~10% in both views (selection reads via
outline, not opacity) and coverage hides mob tokens only — the GM view sees
everything under its own veils.* Drag commits once
on release; tap edits HP/visibility/scale; map pan/zoom, fog tools, stage reset
and initiative remain. NPC HP is token-owned; PC HP persists on the campaign
PC artifact.

Generated layouts stamp normalized rows/columns on the board. Grid tracks,
snapping, fog resizing/coverage and token size derive from those cells on every
viewport. One fog veil covers each room's mob rectangle; room mobs begin
visible underneath it (seen by the GM, hidden by it in player view), while PCs
spawn inside the entry-room rectangle. Uploaded maps with no layout retain the
legacy pixel-grid behavior. Amended 2026-09-06 by cbe8218: *panning starts
from the map image and content background too — a pointer-down on the map was
previously a dead zone that only the letterbox escaped.*

## Screen: Campaign picker (`/`)

Card grid of campaigns (name, system badge, artifact count, updatedAt) +
"New Campaign" card → dialog with name, system select (`GameSystem` values),
description textarea. Delete via card menu with confirm dialog (cascades:
artifacts, revisions, runs).

## Screen: Workspace (`/c/:campaignId`) — the main three-pane layout

Resizable panes (shadcn `resizable`), min widths 220 / 400 / 320 px.

### Left pane — Campaign tree
- Header scope control: Library / Campaign / Module, persisted in settings.
  Workspace defaults to Campaign + Module; Library starts off.
- Library rows appear only in the dedicated **Library** group. Module-owned
  rows appear under their module; remaining rows use kind groups.
- Rows show name, summary tooltip and active state. Filter matches name/tags.
- Context menus include rename/delete and explicit ownership transitions:
  eligible kinds can be published to Library after a loud shared-content
  confirmation; global rows can be adopted into a selected campaign.

### Center pane — Artifact editor
- Header: editable name, kind and revision badges, ownership actions, and a
  prominent amber **Library** badge for shared Library rows. Module-owned
  rows show an **Open in module** link into the module reader (the inverse of
  the peek modal's "Open in workspace"). The
  revision indicator ("rev 7") opens a dropdown listing revisions
  (timestamp + source); selecting one shows read-only snapshot with a
  "Restore this revision" button (restore = save as new revision).
- Run battle (encounters): an encounter open in the editor can seed a battle
  without opening the module reader. A module-owned encounter shows **Run
  battle** anchored to its own module; a campaign- or Library-scoped
  encounter shows **Run battle…**, which opens a minimal picker over the
  campaign's modules (title + artifact count, arrow-key navigable; with no
  modules it shows a named empty state explaining that battles anchor to
  modules). Both paths reuse the module view's `RunBattleButton` and its
  two-step "Replace running battle?" confirm — seeding still anchors per
  module (10-MILESTONE-6 D10) and replaces a running board only after
  confirmation.
- Aliases: an "Also known as" chip input directly below the tags row in the
  header (all kinds — 08-MODULE-DESIGNER M4-A). Enter or comma adds, ×
  removes. Input is trimmed; empty input is ignored; duplicates — and an
  alias equal to the artifact's own name — are rejected case-insensitively
  (`resolveWikiLink` matches the name first, so such an alias could never
  resolve). Stored spelling is preserved verbatim; resolution lowercases on
  its own. Removing an alias never rewrites module text: a prose `[[Name]]`
  that only matched via the removed alias simply becomes an unresolved
  wiki-link, handled by the existing stub/adopt flow.
- Body: markdown editor for `body` — plain `<textarea>` with a Preview toggle
  rendering via `react-markdown`. **No WYSIWYG editor in M1.**
- Kind-specific form below the body, plain labeled inputs mapped 1:1 to the
  `data` fields from 01-DATA-MODEL (e.g. NPC: appearance, personality;
  pointsOfInterest/ranks as add/remove row lists).
- Stat block (NPC): rendered as a classic stat-block card (name line, AC/HP/
  Speed row, ability score grid, traits/actions lists) with an "Edit" toggle
  switching to a form. "Remove stat block" / "Add stat block" buttons.
- Links section: list of `relation → target name` rows (target is a
  combobox over campaign artifacts), add/remove.
- Mentions section ("Mentioned in", 14-BACKLINKS-ORPHANS): read-only
  panel directly below the Links section listing every wiki-link mention
  of this entity across all modules — one row per (module, document)
  with module title, Premise/Part N and ×count, each row deep-linking to
  the reader location. Alias-only matches merge in (a "Mentioned as"
  line names the spellings); an ambiguous winner shows ⚠. Wiki-link
  mentions only — curated relations stay in the Links section above.
  Derived at read time, uncapped, nothing persisted.
- Encounter Battlemap section: upload/select a map or launch **Generate layout
  & map**. When a map is on file the section shows a clickable preview
  thumbnail plus the room count of the stored layout; the action button reads
  **Regenerate**. Regenerate hands the existing artifact to Encounter
  Cartographer; identity, prose, links and roster stay fixed while layout/map
  are replaced. The pre-filled brief in the persona panel says "Generate…" for
  a mapless encounter and "Regenerate…" only when a map already exists.
- Saving: autosave with 800 ms debounce; every autosave that changed content
  creates a revision. Show "Saved" / "Saving…" text near the header.

### Right pane — Persona panel (tabs: **Assistant** | **Runs**)

**Assistant tab**
- Persona select (dropdown of personas), autonomy select
  (Manual / Review / Auto, default Manual), brief textarea, "Pinned rules"
  list (added from Rules browser; removable chips), Start button
  (disabled without API key → hint linking to Settings).
- Active run view: vertical step list (retrieve / draft / statblock /
  finalize) with status icons; a global target repeats the **Global** warning
  badge. The running step shows streamed tokens in a monospace scroll area.
- On `awaiting_user`: step card shows the parsed output rendered nicely
  (draft = the NPC fields; retrieve = chunk list with checkboxes to drop
  chunks) with buttons **Approve**, **Edit** (opens a JSON/text editor for the
  step output), **Retry…** (optional instruction input), **Cancel run**.
- Encounter Cartographer adds a persisted 4:3 / 16:9 / 1:1 aspect select.
  Brief and layout checkpoints are editable; layout review shows labeled room
  and mob rectangles. Candidate maps carry the same overlay plus red vision
  diff cells, and exactly one map is selected. Auto mode picks candidate one.
- On completion: success banner with "Open artifact" button.

**Runs tab** — table of past runs (persona, brief truncated, status,
updatedAt); clicking shows the read-only step log.

**Writers' room tab — module forge progress visibility**
- While the forge runs, a status line reads
  `Generating module — step X of Y: <step title>` (refinement phase reads
  `Refinement pass — …`).
- The step plan is listed with human-readable titles (Plot arc, Session 1,
  Key location 1, …, Continuity review, Refine: "<artifact>") and per-step
  state badges.
- Finished steps name the artifact they produced (`→ <artifact name>`).
- The currently running step shows a live tail of the streamed tokens
  (monospace preview, last ~400 chars).
- When a step fails (LLM error, invalid JSON after retry), the forge does
  **not** restart: a `Retry failed step` button re-runs only the failed step
  as a new run, feeding it the artifacts of every completed step before it,
  then continues the remaining plan (including the refinement pass when the
  generation phase completed). The failed run stays in the Runs tab with its
  error message. The chain builder has the same retry affordance.

## Screen: Rules (`/rules`)

Two-pane:
- Left: book list (title, system badge, status chip incl. processing progress
  bar, chunk count, menu: Rename / Set system / "Embed whole book" / Delete)
  + "Import PDFs" button (multi-file input).
- Right: search box (searches on Enter / 300 ms debounce), filters (book
  multi-select, chunkType checkboxes), result list: heading path as
  breadcrumb, book + page badge, text snippet with highlighted terms,
  source badge (kw/sem/both). Clicking a result expands the full chunk text
  (stat blocks render with the stat-block card). Each result has a
  **"Pin to Assistant"** button (adds to a global zustand pin list consumed by
  the persona panel; toast confirms).

### Bestiary packs (delta for 12-BESTIARY-PACKS §6/§8)

- Next to "Import PDFs" a second **"Import bestiary pack"** button opens a
  dialog: adapter select (registered adapters only), a multi-file input
  (`.json` / `.db` / `.yml` / `.zip`), then the import report — imported /
  skipped / failed counts with an expandable failed-entries list. While the
  import runs, the new book's processing chip reports done/total progress
  exactly like PDF page progress; a zero-entry import ends in a loud
  `error` book + toast (no empty ready book).
- Pack book cards carry a **Pack** badge, and the book menu gains a
  **License** item showing `packMeta.license` verbatim.
- Monster entries resolved from a pack chunk print the origin label
  `"<bookTitle>: <creatureName>"` instead of a page number (packs have no
  pages); PDF chunks keep `"<bookTitle> p.<pageStart>"`.

## Screen: Settings (`/settings`)

- OpenRouter API key (password input, "Test key" button calling
  `GET /api/v1/models` and reporting ok/fail).
- **First-try chat model** (workhorse; cheaper is fine) + **Fallback chat
  model** (escalation tier — used on congestion, content refusal, or one
  contract-repair attempt; empty = no fallback and failures stay loud) +
  embedding model (text inputs with the defaults from 01-DATA-MODEL
  prefilled; below each a combobox of models fetched from `/models` when key
  is valid).
- Embeddings enabled toggle.
- **Parallel requests** (1–4, default 2): how many INDEPENDENT generation
  requests run at once — entity batch runs, background image-queue jobs, and
  encounter-map verifications. Dependent chains (module parts, writers' room)
  stay sequential regardless of this setting. Free OpenRouter models cap at
  20 requests/minute, so keep the level low when using `:free` models.
- Image generation section (M3-A): enabled toggle; **First-try image model**
  and **Fallback image model** (browse lists filtered to
  `output_modalities=image`; the fallback runs only when the first-try model
  is congested or refuses); **Encounter map verify model**
  (M6, browse list filtered to models that accept image input AND produce text
  output — the verify step sends the generated map to a chat model; empty =
  default chat model).
- Personas section: list of personas; expanding one shows editable name,
  description, model (blank = default), temperature slider, system prompt
  textarea; "Reset to default" for built-ins.
- Backup & restore (M4-C): "Save everything" zips the ENTIRE IndexedDB state
  (all campaigns, artifacts, rulebooks, chunks, embeddings, personas, runs,
  deliverables, modules, images) into `campaigner-backup-<date>.zip`;
  "Load everything" restores one, REPLACING all current data after a confirm
  dialog. The OpenRouter API key never leaves the browser: it is stripped
  from saves and the locally stored key survives restores. Browsers with the
  File System Access API get native save/open dialogs; the rest fall back to
  a plain download and a file input. The save destination is acquired
  FIRST, inside the click's user-gesture window, and the zip is written to
  it after the build — the native picker requires transient activation,
  which a large backup build would otherwise outlive.
- Storage persistence status line: shows whether the browser committed to
  keeping the IndexedDB (`navigator.storage.persist()` is requested on app
  start); hints at home-screen installation when storage is best-effort.
- Danger zone: "Delete all data" (confirm by typing DELETE).

## Tablet & PWA support (landscape-first)

Campaigner is a dense landscape workspace (~1000px pane minimums); portrait
and narrow viewports are unsupported by design.

- Orientation gate: pure-CSS hard blocks rendered by the app shell —
  `orientation-gate.tsx` shows a rotate prompt on any portrait viewport and a
  "screen too narrow" message on landscape viewports under ~960px (iPhone,
  Split View). Applies in the browser tab and installed alike: WebKit
  supports neither the manifest `orientation` member nor
  `screen.orientation.lock()`, so the overlay is the only real enforcement.
- Installable PWA: `public/manifest.webmanifest` (standalone, landscape,
  relative entry points so non-root Vite bases work), PNG icons generated
  from `favicon.svg` (incl. a maskable variant), and `public/sw.js` caching
  the app shell — network-first for navigations with an offline fallback,
  cache-first for hashed `/assets/`, cross-origin and non-GET requests
  (OpenRouter) untouched. Registered production-only from `main.tsx`.
- Home-screen installation is the strongly preferred mode on iPad: standalone
  window, and WebKit exempts installed home-screen web apps from ITP's 7-day
  script-writable-storage cap (data eviction) — verified against
  webkit.org's tracking-prevention policy. iOS has no programmatic install
  prompt, so a one-time hint (`install-hint.tsx`) explains
  Share → Add to Home Screen on touch devices running as a browser tab;
  dismissal persists in localStorage.
- Safe areas: the shell pads with `env(safe-area-inset-*)` (top/left/right on
  the frame, bottom under the Toaster and ProgressDock) so fixed UI clears
  the status bar and home indicator in landscape.
- Touch behavior: interactive elements opt out of double-tap zoom
  (`touch-action: manipulation` — pinch zoom stays available); Buttons grow
  their hit box by ±4px via a `pointer: coarse` pseudo-element (no visual or
  layout change); hover-revealed controls (tree-row and run delete buttons)
  render permanently on coarse pointers; quick find has a top-bar button —
  the Ctrl/Cmd+K hotkey is unreachable on an on-screen keyboard.
- Fullscreen image gestures (`zoomable-image.tsx`): pinch zoom anchored on
  the gesture midpoint, one-finger pan clamped to the scaled overflow,
  double-tap toggles 2.5×, wheel zooms with a pointer, tap closes at fit
  scale (deferred past the double-tap window), plus an explicit close button.
- Startup images: `scripts/generate-splash.mjs` emits a solid
  `background_color` fill per iPad class × orientation × pixel ratio
  (`public/splash/`), linked from `index.html`; `apple-mobile-web-app-capable`
  and `apple-mobile-web-app-status-bar-style: black-translucent` cover
  pre-manifest iPadOS and the full-bleed status bar. WebKit accepts a splash
  only on an exact media match — the `pwa-assets` test parses each link and
  asserts the PNG's IHDR dimensions, so a mismatch fails CI.

### Battle surface — iPad hardening backlog (notes only, not scheduled)

Documented risks on the M5-D table surface (09-MILESTONE-5) for on-device
iPad use, added 2026-09-06 from the battle-table fixes pass (d0c7fc8,
0275d27, fba12b7). Nothing here is scheduled — notes so the next tablet
pass starts from the real list, not a fresh audit:

- Initiative sidebar drag-to-reorder uses HTML5 drag-and-drop
  (`draggable` + `onDragStart`/`onDragOver`/`onDrop`), which is unreliable
  on iPadOS Safari — migrate to Pointer Events.
- Veil resize handles are 12px click targets (`size-3`) — far under the
  44px minimum; grow them and switch click-to-resize to drag-resize (the
  M5-D spec defers drag-resize here explicitly).
- Pinch-zoom and one-finger pan/drag share the board's single
  pointer-tracking flow; a second finger landing mid-drag can fight the
  active gesture's pointer capture (the pinch path clears pan state
  mid-gesture). Needs an on-device gesture audit.
- Zoom is effectively wheel-zoom only in practice: the board handles wheel
  and the toolbar buttons, and a two-finger pointer pinch exists, but
  iPad's synthesized wheel/gesture events are unverified on-device — until
  proven, assume touch zoom must go through the buttons.
- The coarse-pointer art overlay (screen-space token rendering) from the
  original M5-D spec was dropped to the M5-D parking lot — it never
  shipped; see 09-MILESTONE-5 §M5-D before re-proposing it.

### Manual on-device checklist

Run against the HTTPS deploy — LAN/dev HTTP is an insecure context: no
service worker, no `navigator.storage`.

1. Install: open the deployed URL in Safari → Share → Add to Home Screen;
   the app launches standalone, landscape, with no white flash.
2. Orientation gate: portrait shows the rotate prompt; Split View under
   ~960px shows the "too narrow" message.
3. Storage: Settings → Backup & restore shows "Storage is persistent"; force
   Safari closed and reopen after 8+ days without use — data survives
   (installed home-screen web apps are exempt from ITP's 7-day cap).
4. Offline: airplane mode → relaunch from the home screen → app shell loads
   from the service worker.
5. Touch interactions: quick find opens from the top-bar Find button;
   tree-row long-press opens the context menu; resizable panes drag with a
   finger; fullscreen images pinch-zoom, pan and double-tap; rapid double
   taps on buttons never zoom the page; hover-revealed deletes are visible.

## Empty/edge states (implement all)

- No campaigns → picker shows hero text + create button.
- No artifacts in a section → muted "No NPCs yet — create one or ask a persona."
- No books → rules screen hero with import button.
- No API key → persona Start disabled with inline hint; Settings link.
- Book status 'error' → red chip, tooltip shows errorMessage, Retry menu item
  (re-runs ingestion if the user re-selects the file — original bytes are not
  stored).

## Top bar — generation language

The top bar carries a language select (globe icon) on every route, including
the main page: it picks the language all generation prompts must produce
(default English) and persists it in the settings row (`language`). The same
control appears on the Settings page.

## Screen: Deliverable builder (`/c/:campaignId/deliverables`) — M3-D

Left: deliverable list (+ create). Right: outline editor — nested chapters /
parts / artifacts / text / galleries with add and up/down/remove buttons (no
drag-and-drop libs), per-artifact include toggles (body / data / stat blocks /
images), audience switch (GM / Player), and a cover image picker over campaign
images. "Generate PDF" renders via pdfmake (cover, ToC, chapter banners with
kickers, read-aloud boxes, two-column stat boxes, ≤45%-width images, NPC
gallery + treasure ledger appendices) and downloads the file. "Seed from
module" maps premise and parts plus resolved owned entities. Module-owned
artifacts are included normally; a global Library row appears only when the
user explicitly adds its artifact node—never through seeding or an automatic
gallery/ledger.
