# 05 — UI Specification

Tailwind + shadcn/ui, dark mode default (GM-at-the-table friendly), light mode
toggle in the top bar. Routing via react-router.

## Routes

```
/                              → campaign picker
/c/:campaignId                 → three-pane workspace
/c/:campaignId/a/:artifactId   → workspace with artifact open
/c/:campaignId/graph           → link graph
/c/:campaignId/modules         → module list
/c/:campaignId/m/:moduleId     → module reader (the only play view)
/c/:campaignId/m/:moduleId/battle → module's live battle table
/c/:campaignId/deliverables    → deliverable builder
/rules                         → rules library
/settings                      → settings
/guide                         → first-module guide (chapter 1)
/guide/:chapterId              → one guide chapter (opens in another tab)
```

Top bar: app name, campaign switcher, Rules / Settings navigation, the
last-module shortcut (arrow + the name of the module whose reader was opened
last, one click back to it — hidden until a reader has been opened), New
Module on campaign routes, Ctrl+K quick-find, generation language, help and
theme. Directly below it, the **campaign bar** renders the campaign-level tabs —
Modules / Workspace / Deliverables / Graph, Modules first (the central view
the rest feeds) — on every route, disabled (with an
"Open a campaign first" hint) while no campaign is open. On nested screens the
bar's right side shows a breadcrumb (Campaigns / Modules / *module title* / Battle
table), so deep screens always state where they are and exit in one click.
The retired `/play` route and `▶ Play` button do not exist.

### Quick-find (Ctrl+K)

The palette follows the workspace scope preference. Artifact hits search
name/tags/summary/aliases; global hits are labeled **Library**. Module/part and rule
hits share the palette. Enter navigates to an artifact or module; rule hits
open an inline preview with **Pin to Assistant**. With an empty query the
palette lists a **Go to** group — the campaign sections (Workspace, Modules,
Deliverables, Graph), Rules and Settings, and **Battle table (this module)**
on a module reader screen — so Ctrl+K doubles as an app map.

## Progress dock

The app-wide dock reports every slow task (batch generation, module parts,
PDF builds). Its header hosts **Stop all**, which sweeps every running
generation (job queues, in-flight runs, the module forge, a running chain) —
non-destructive, stopped runs stay resumable. Jobs that live somewhere (a persona run, a module mid-forge)
render their label as an **Open** button that navigates to the job — a run
opens preselected in the workspace persona panel (`?run=`), a module opens in
its reader. A module that is being forged also shows the live step ("Writing
part 2 of 5: …") on its Modules list row.

## Screen: Module reader (`/c/:campaignId/m/:moduleId`) — M6

The module reader is the only play view: table of contents/search on the left,
adventure prose and wiki-link chips in the center, entity panel on the right.
Its shared Library / Campaign / Module scope control defaults to all scopes.
**Battle table** opens the module's live board — offered both in the reader
header (a mode change, visible even with the contents sidebar collapsed) and
in the contents sidebar. Encounter rows offer **Run battle**. Module-owned
rows can be adopted back into the campaign. Recorded
encounter entities can be batch-detailed, and **Generate encounter maps** runs
a one-candidate unattended queue for module encounters still lacking layouts;
failures remain retryable and do not stop later jobs. The header mounts the
module cover hero (cover-generation arc: `ModuleCoverHero` — the banner
renders only when the module has cover art) with **Generate / Regenerate
cover** beside the other header actions; the modules list row mounts the
cover thumb (`ModuleCoverThumb`) with a compact icon-only generate
affordance. Both displays resolve through `useImageUrl(coverImageId)` — the
same artifact-cover path as the play cards — and render nothing while
loading/missing (no placeholder art). The reader and the list never render
in player-safe mode (the battle player-safe DOM contract mounts board
material only), and every other reader control is already an un-gated GM
control — so the Generate buttons join that set with no extra gate; covers
are shared art, never secrets (the player-audience PDF strips GM-only
material at render, covers round out the page as art).

### Part text editor (find/replace)

The ✎ affordance on a ready part (hidden otherwise) swaps that chapter to an
inline editor: the shared markdown textarea with a find/replace toolbar
above it — find with `active / total` match count, Enter/Shift+Enter and
prev/next buttons jumping the draft selection, an **Aa** case-sensitive
toggle, **Replace** (active match) + **Replace all**, a Preview toggle
rendering through the shared wiki-link pipeline, and **Save part** /
**Cancel**. Save persists to the module row with the `edited` flag and a
"Part saved" toast (blur also saves unless focus stays inside the editor);
Cancel discards without touching the row. A part saved this way shows the
hand-edited overwrite warning in the **Rewrite part** dialog, whose Cancel
is inert and whose confirm regenerates just that part.

### Stub generation ownership (integrity-fix arc)

The unresolved-chip popover's **Generate** runs the same chain machinery as
the batch, and its artifact is **module-owned from birth**: the chain step
carries `placementModuleId` (persisted on the run row, so pause/resume/retry
keeps it), and the post-run `stampModuleOwnership` call is the idempotent
`module:<title>` tag/history write only — ownership never depends on
surviving until after the run. If the owning module is deleted while a run is
in flight, the run FAILS loudly at finalize (failed run row + toast) instead
of creating an artifact owned by a module that no longer exists.

### New Module dialog — automation grid

The "After the parts are written" grid carries the per-kind Generate/Image columns plus the "Generate encounter battlemaps" (default ON) and "Generate encounter mob images" (default OFF) toggles; after the parts finish, the sweep runs the checked automations — unresolved entities detailed, images queued, battlemaps and one canonically-cached mob portrait per rulebook-cited roster creature per encounter (docs/08 §Post-generation automation).

### Module deletion contract (Modules list → confirm dialog)

The confirm dialog shows the LIVE owned-artifact count and re-counts at
confirm time; the chosen branch (cascade / keep) applies to the rows that
exist at delete time — never to the count that was live when the dialog
opened, and never to a partial application (the whole disposal is one
transaction; a mid-cascade failure rolls everything back, module row
included). Deleting a module also aborts its in-flight spine/parts pass.
The contract: **in-flight runs fail loudly, already-finalized rows
cascade/release, nothing dangles.**

### Fresh-generation wipe (Edit campaign → danger zone)

**Remove all generated content…** deletes everything generation produced in
the campaign — every non-`pc` artifact (campaign- and module-owned, revisions
scrubbed through the artifact delete path), every module row, every battle,
and the campaign runs + deliverable outlines that would dangle into deleted
rows — so generation can restart clean while the Party (`pc` artifacts,
untouched with their revisions/images/links), the campaign row, settings,
personas and the global library survive. The two-step confirm lists LIVE
counts by kind + module/battle counts and requires an explicit confirm (no
typing); the execute path re-lists everything inside ONE transaction (dialog
counts never decide what goes), so any failure rolls the whole wipe back
loudly — a partial wipe with a success toast is impossible. In-flight module
passes abort first; their runs fail loudly at finalize. The action lives in
the campaign settings surface only — never in the tree or another
high-traffic spot.

## Screen: Campaign picker (`/`)

Card grid of campaigns (name, description snippet — line-clamped, shown only
when set —, system badge, artifact count, updatedAt) + "New Campaign" card →
dialog with name, system select (`GameSystem` values), description textarea.
The card menu offers **Edit campaign…** — a small dialog for name and
description (empty description is valid) plus the **Remove all generated
content…** danger zone (fresh-generation wipe, above); the game system is
shown read-only
because stat blocks and battles depend on it. Delete via card menu with
confirm dialog (cascades: artifacts, revisions, runs). Opening a campaign —
card click or top-bar switcher — lands on its **Modules** view (the central
view); that landing's header repeats the campaign name + description (muted,
clamped, only when set) and carries the same **Edit campaign** affordance.
Each picker card mounts the campaign cover art (cover-generation arc:
`CampaignCoverArt` — renders only when the campaign has cover art, card
shape never shifts for cover-less campaigns) with **Generate / Regenerate
cover** in the badge row; the art resolves through `useImageUrl(coverImageId)`
and renders nothing while loading/missing.

**Import** (picker toolbar, `.json` / `.zip`): parse-first with a
missing-dependency gate (07-MILESTONE-3 M3-E slice B). The file is parsed and
its `dependencies` manifest analyzed against the local library BEFORE the
import transaction opens — a clean manifest keeps the one-click path
(toast + land on the new campaign's Workspace). Unmet statblock citations
(L0-miss: neither byte-identical content nor an equivalent book) or NPC refs
outside the export open a dep-summary dialog instead: per-book `{title,
system, cited count, matchLevel}` badges (present / version drift / similar
content / missing) plus the citing encounters (`encounter → creature`) and
the unmet NPC refs, with the resolve path named (Rules → "Import bestiary
pack", or re-import the rulebook PDF — deep-linked). **Abort** is the
default (Cancel / Esc / backdrop — never enters the transaction, so there is
nothing to roll back); **Import anyway** lands the encounters as-is, where
they resolve to the existing `missing ref` markers until the content is
installed, and the campaign shows the missing-refs banner (below the
campaign bar, on every campaign route — derived from the same
`resolveMonsterEntry` contract as the row badges, so the two can never
disagree; it clears itself when the content arrives).

**Export** (card-menu dialog with artifact selection + JSON/zip formats, tree
single-artifact JSON, tree artifact PDFs) rides the same save seam as Backup
& restore below: the native save dialog opens FIRST, inside the click's
gesture window (JSON/zip/PDF picker types per format), and the built file is
written to it afterwards. Cancelling the native dialog builds nothing and
toasts nothing — the campaign dialog stays open with its selection intact.

## Screen: Workspace (`/c/:campaignId`) — the main three-pane layout

Resizable panes (shadcn `resizable`), min widths 200 / 360 / 280 px
(840 total — the default 22/48/30 layout clears every floor at 1024px iPad
landscape; narrower viewports are NOT gated — the landscape layout simply
renders at whatever width is offered). The right
(persona) pane is collapsible via drag so cramped screens can reclaim it; the
tree and editor never collapse. Campaign tree rows reach 44px on coarse
pointers (`pointer-coarse:min-h-11`, desktop rows unchanged).

### Left pane — Campaign tree
- Header scope control: Library / Campaign / Module, persisted in settings.
  Workspace defaults to Campaign + Module; Library starts off.
- Library rows appear only in the dedicated **Library** group. Module-owned
  rows appear under their module; remaining rows use kind groups. A
  module-owned row whose module row is missing renders in an explicit
  **Orphaned** group (amber `orphaned` badge per row) — never silently
  blended into the kind groups — with a one-click **Re-anchor to campaign**
  context action (`adoptIntoCampaign`/moveScope) as the sanctioned fix.
- Rows show name, summary tooltip and active state. Filter matches name/tags.
- Context menus include rename/delete and explicit ownership transitions:
  eligible kinds can be published to Library after a loud shared-content
  confirmation; global rows can be adopted into a selected campaign.

### Center pane — Artifact editor
- Header: editable name, kind and revision badges, ownership actions, and a
  prominent amber **Library** badge for shared Library rows. Module-owned
  rows show an **Open in module** link into the module reader (the inverse of
  the peek modal's "Open in workspace"). The
  revision indicator ("rev 7") opens a dropdown listing revisions
  (timestamp + source); selecting one shows read-only snapshot with a
  "Restore this revision" button (restore = save as new revision).
- Run battle (encounters): an encounter open in the editor can seed a battle
  without opening the module reader. A module-owned encounter shows **Run
  battle** anchored to its own module; a campaign- or Library-scoped
  encounter shows **Run battle…**, which opens a minimal picker over the
  campaign's modules (title + artifact count, arrow-key navigable; with no
  modules it shows a named empty state explaining that battles anchor to
  modules). Both paths reuse the module view's `RunBattleButton` and its
  two-step "Replace running battle?" confirm — seeding still anchors per
  module (10-MILESTONE-6 D10) and replaces a running board only after
  confirmation. Amended 2026-09-06 (encounter-resume arc, resume-by-default):
  *a module whose running battle was seeded from THIS encounter shows
  **Open battle** instead — a plain navigation that reattaches the persisted

  explicit two-step **Re-run battle** → "Replace running battle?" path. A

  Speed row, ability score grid, traits/actions lists) with an "Edit" toggle
  switching to a form. "Remove stat block" / "Add stat block" buttons.
- Links section: list of `relation → target name` rows (target is a

- Mentions section ("Mentioned in", 14-BACKLINKS-ORPHANS): read-only

  Derived at read time, uncapped, nothing persisted.

  requests run at once — entity batch runs, background image-queue jobs.

  stay sequential regardless of this setting. Free OpenRouter models cap at
  20 requests/minute, so keep the level low when using `:free` models.
- Image generation section (M3-A): enabled toggle; **First-try image model**

- Appearance (UI scale): a six-step select — 90% / 100% (default) / 110% /
  125% / 150% / 200% — that scales controls and text app-wide; battle-map boards and 3D
  dice are unaffected. The choice is a device display preference persisted in
  localStorage (`campaigner.uiScale`, riding the theme's pattern — never in
  the settings row, so it stays out of the data DB and backups) and survives
  Delete-all-data like the theme. Mechanism: a `--ui-scale` CSS var (default
  1) multiplied into the root font-size — the app is rem-based, so one var
  scales spacing/text/radii — applied app-wide by `useUiScaleSync` in the
  shell. Deliberately NOT CSS zoom (it breaks board/pointer px math and
  Firefox); the intentionally fixed-px surfaces are listed in
  18-ARCHITECTURE §4.
- Personas section: list of personas; expanding one shows editable name,
  description, model (blank = default), temperature slider, system prompt
  textarea; "Reset to default" for built-ins.

  (all campaigns, artifacts, rulebooks, chunks, embeddings, personas, runs,
  deliverables, modules, images) into `campaigner-backup-<date>.zip`;
  "Load everything" restores one, REPLACING all current data after a confirm

  from saves and the locally stored key survives restores. Browsers with the

  which a large backup build would otherwise outlive.

## Tablet & PWA support (landscape-first)

Campaigner is a dense landscape workspace (~840px pane minimums); portrait
and narrow viewports are NOT blocked (owner decision 2026-09-09 — no
orientation gate; the layout renders at any width, narrowly when narrow).

- Installable PWA: `public/manifest.webmanifest` (standalone, landscape,
  relative entry points so non-root Vite bases work), PNG icons generated
  from `favicon.svg` (incl. a maskable variant), and `public/sw.js` caching
  the app shell — network-first for navigations with an offline fallback,
  cache-first for hashed `/assets/`, cross-origin and non-GET requests
  (OpenRouter) untouched. Registered production-only from `main.tsx`.
- Home-screen installation is the strongly preferred mode on iPad: standalone
  window, and WebKit exempts installed home-screen web apps from ITP's 7-day
  script-writable-storage cap (data eviction) — verified against
  webkit.org's tracking-prevention policy. iOS has no programmatic install
  prompt, so a one-time hint (`install-hint.tsx`) explains
  Share → Add to Home Screen on touch devices running as a browser tab;
  dismissal persists in localStorage.
- Safe areas: the shell frame pads with `env(safe-area-inset-*)` on all four
  sides (top/left/right plus bottom, so content clears the home indicator
  when the ProgressDock is empty) while the Toaster and ProgressDock keep
  their own bottom offsets exactly once (fixed layers ignore the frame pad —
  no double-padding); dialog content clamps to `max-h-[calc(100dvh-2rem)]`
  with scroll so short-landscape dialogs never clip under the URL bar.
- Touch behavior: interactive elements opt out of double-tap zoom
  (`touch-action: manipulation` on buttons, links, `[role=button]`, summaries,
  select/tab/context-menu triggers — pinch zoom stays available); Buttons grow
  their hit box via a `pointer: coarse` pseudo-element (±6px pad, so a 32px
  button reaches the 44px finger target with no visual or layout change) while
  the sub-32px button sizes (xs/sm/icon-xs/icon-sm, incl. the dialog close
  button) carry a 44px coarse-pointer minimum; checkbox, resizable-handle and
  tab triggers likewise reach 44px on coarse pointers (transparent hit pads /
  44px tab row, visuals unchanged); hover-revealed controls (tree-row and run delete buttons)
  render permanently on coarse pointers; quick find has a top-bar button —
  the Ctrl/Cmd+K hotkey is unreachable on an on-screen keyboard.
- Fullscreen image gestures (`zoomable-image.tsx`): pinch zoom anchored on
  the gesture midpoint, one-finger pan clamped to the scaled overflow,
  double-tap toggles 2.5×, wheel zooms with a pointer, tap closes at fit
  scale (deferred past the double-tap window), plus an explicit close button.
- Startup images: `scripts/generate-splash.mjs` emits a solid
  `background_color` fill per iPad class × orientation × pixel ratio
  (`public/splash/`), linked from `index.html`; `apple-mobile-web-app-capable`
  plus the modern `mobile-web-app-capable`, `apple-mobile-web-app-title`,
  and `apple-mobile-web-app-status-bar-style: black-translucent` cover
  pre-manifest iPadOS and the full-bleed status bar. The viewport stays
  zoomable (no maximum-scale / user-scalable=no). WebKit accepts a splash
  only on an exact media match — the `pwa-assets` test parses each link and
  asserts the PNG's IHDR dimensions, so a mismatch fails CI.

## Empty/edge states (implement all)

### Error surfaces (toasts never raw JSON)

Every error toast carries mitigation, not just cause, and no toast ever
renders a raw error dump: a ZodError's `.message` IS the raw
`[{code,path,message}...]` array, so the toast seam (`lib/toast.ts`,
humanize-at-the-seam rule in 18-ARCHITECTURE) renders a counted, grouped,
capped summary instead — table + index per record (`artifacts[2]`), first 3
issues plus "and N more", the version-skew mitigation ("update this
instance (or the exporting one) to the same version and try again"). Record
names are never invented (zod issues carry no input values); a context that
HAS the rows names its own records. The full raw error goes to the console
(one click away in devtools, never megabytes in the toast). Import failures
specifically append the same mitigation via
`lib/exportImport.withImportMitigation` (Zod-shaped and
`MissingDependenciesError` failures already carry theirs), and the
`MissingDependenciesError` message itself reads as numbered steps (Rules →
"Import bestiary pack" + missing titles → retry, or the import-anyway
consequence) because it also surfaces outside the dep-summary dialog.

- No campaigns → picker shows hero text + create button.
- No artifacts in a section → muted "No NPCs yet — create one or ask a persona."
- No books → rules screen hero with import button.
- No API key → persona Start disabled with inline hint; Settings link.
- Book status 'error' → red chip, tooltip shows errorMessage, Retry menu item
  (re-runs ingestion if the user re-selects the file — original bytes are not
  stored).
- First run → the setup wizard auto-opens once (fresh status + zero campaigns);
  otherwise its entry points surface on the picker, welcome panel and help.

## Onboarding (setup wizard + first-module guide) — M-onboarding

### Screen: Setup wizard (dialog, all routes)

A first-run **welcome + setup wizard** mounted once in the AppShell (like the
help dialog) and backed by the settings row's `onboarding` field:
`status: fresh | active | dismissed | complete` plus per-step entries
(missing = pending). A checklist, not a stepper — six steps that link OUT to
the surfaces that already do the work:

1. **Welcome** (in-dialog): what Campaigner is, local-first, the key is a paid
   service. Resolves on **Begin**.
2. **OpenRouter key** → Settings. Auto-ticks when a key is saved. Copy states
   what the key is, that OpenRouter is paid (≈$3/M tokens default model, a few
   cents per run), where to get one (openrouter.ai/keys), and that the key is
   stored only in this browser and sent only to openrouter.ai.
3. **Generation language** (optional) → top bar / Settings. Auto-ticks when
   non-English; the default is fine.
4. **Rulebook** (optional) → Rules. Auto-ticks when a book exists. Copy notes
   the loud scanned-PDF failure and that original bytes are never stored.
5. **Bestiary pack** (optional) → Settings. Manual mark only (fetched packs
   aren't cheaply detectable).
6. **First campaign + module** → picker / top-bar Module, plus the
   **First-Module Guide** in a new tab. Auto-ticks when a campaign AND a module
   exist; shows live ✓/· sub-progress.

Semantics: every step is skippable; detected completions tick automatically;
the dialog resumes at the first unresolved step; **Finish** (all resolved)
persists `complete`; **Don't show again** persists `dismissed` and never
auto-opens again. Auto-open fires once per browser and only when campaigns ==
0 (an upgraded install is never hijacked). Re-open affordances: picker header
"Get set up" + empty-card "Set up Campaigner" button, the workspace welcome
panel, and the help **setup** topic's "Reopen the setup wizard" action. All
hidden once complete (picker/welcome; help topic stays).

### Screen: First-module guide (`/guide`, `/guide/:chapterId`)

A full-page in-app route authored as structured data (`guideContent.ts`,
helpContent pattern) and opened **in another tab** (`target="_blank"`) from
the wizard's last step, the help setup topic and the modules empty state — a
same-origin tab keeps IndexedDB, so it can deep-link the reader's own
campaign. Nine chapters teach the authored path: start here → campaign →
rules & pins → create module → approve the spine → read/edit/rewrite →
resolve the cast → battlemaps → table & print. Each chapter ends with a
checkpoint line and a "Do it now" button: static routes always resolve;
campaign-scoped ones resolve against the most recently updated campaign and
render as a disabled hint while none exists. A test guarantees content
completeness and that every app link's route exists in the route table.
